/*
Представлен другой рекурсивный алгоритм для поиска наименьшего элемента слайса.
Вычислите его сложность, используя изученные формулы.
Сравните эффективность алгоритма с предыдущим вариантом.
Попробуйте увеличить скорость выполнения функции, используя инструменты Го.
Как изменится сложность алгоритма при увеличении скорости?
*/

func MinEl2(a []int) int {
	// только для первичной проверки
	if len(a) == 0 {
		return 0
	}
	if len(a) == 1 {
		return a[0]
	}
	t1 := MinEl2(a[:len(a)/2])
	t2 := MinEl2(a[len(a)/2:])
	if t1 <= t2 {
		return t1
	}
	return t2
}
    Термины:
    T(n) - время решения задачи, размером n;

    Рекурентное выражение для данного алгоритма:
         T(n) = 2*T(n/2) + n, т.к.
            2 раза происходит вызов рекурсивной функции на половине данных и после n раз происходит сравнение полученных
            результатов.
    Поскольку выход из рекурсивных методов происходит при n=1, то вторым начальным условием будет:
        T(1) = 0

    Применим метод обратной подстановки:
        T(n) = 2*T(n/2) + n                                          подставляем T(n/2) = 2*T(n/4) + n/2,
        T(n) = 2*(2*T(n/4) + n/2) + n = 4*T(n/4) + 2*n               подставляем T(n/4) = 2*T(n/8) + n/4,
        T(n) = 4*(2*T(n/8) + n/4) + 2*n = 8*T(n/8) + 3*n

    Можно заметить закономерность:
        T(n) = 2^k*T(n/2^k) + k*n,
        подставляем значение второго начального условия и получаем:
        n/2^k = 1   =>   k = log2(n), теперь подставим k в полученную из первого начального уравнения формулу:

        T(n) = 2^log2(n)*T(n/2^log2(n)) + log2(n)*n = n*log2(n), т.к.
        T(n/2^log2(n)) = 0, т.к. отражает второе начальное условие.

    Данное решение было рассмотрено для длины массива, которая является точной степенью 2, но при построении дерева
    вызовов можно заметить, что, если длина массива не является точной степенью 2, то глубина дерева вызовов может
    измениться только на 1, т.е. разницей можно пренебречь как константой.

Ответ: сложность данного алгоритма O(n*log2(n))

2. При сравнении данного алгоритма с предыдущим можно заметить, что количество рекурсивных вызовов различно, т.к.
в первом примере рекурсия вызывается лишь n раз, то в данном алгоритме происходит 2*n-1 вызовов, хотя глубина рекурсии
в предыдущем алгоритме равна n, а в данном алгоритме равна log2(n)+1, что значительно меньше.

3. Чтобы уменьшить время выполнения поиска минимального значения в массиве лучше использовать не линейно-
логарифмическую сложность, а линейную, чего можно добиться просто последовательно сравнив все элементы с минимальным и
при необходимости перезаписать минимальное найденное число.

func MinEl3(a []int) int {
   	if len(a) == 0 {
   		return 0
   	}
   	min := a[0]
   	for _, v := range a[1:] {
   		if v < min {
   			min = v
   		}
   	}
   	return min
}
